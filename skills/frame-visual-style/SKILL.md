# 项目视觉风格

由 Codex 读取项目剧本和创作意图，准备充分详细、可复用的风格档案。用户可提供自然语言和参考图，不需要亲自写机器提示词。使用 [视觉风格档案模板](templates/style-bible.md)；保存和执行遵循 [公共制作交接](../../docs/PRODUCTION_HANDOFF.md)。

## 构建详细档案

1. 明确媒介与渲染方式：写实摄影、三维动画、二维动画、定格等，以及真实程度、线条或体积表现。服从项目选择，不固定所有项目为写实。
2. 明确调色：整体色温、主辅色倾向、饱和度、反差和暗部/高光处理。具体色值只有用户指定并完成像素检查才能宣称准确。
3. 细化光线：主光方向与软硬、环境填充、轮廓光、阴影密度、色温与不同场景的合理变化。人物、机器人及不同材质要共享影像风格，但不强行拥有完全相同的反射。
4. 明确材质与纹理：皮肤、织物、金属、塑料、纸张、环境表面应如何表现，控制镜面、粗糙度和磨损范围；不要用某一主体的形态覆盖其他主体。
5. 明确摄影与画面：透视、景深、锐度、颗粒感、镜头气质、构图留白及动态程度；区分可比较的资产标准图和服务剧情的分镜，允许头像、全身和特写有不同景别。
6. 指定空间背景与气氛如何变化：统一光影与材质逻辑，不要求所有素材和镜头复制参考图背景、人物、道具或构图。
7. 记录应避免的少量具体偏差、可变项和必须保持项。详细描述有用的区别，不堆重复或互相矛盾的形容词；事实、创作选择和未知分别标注。
8. 记录来源、版本、模型适配条件、参考图的明确用途与使用权限。参考具名作品时拆解具体视觉特征，不把角色、标识或构图自动复制到新作品。

## 风格参考图

由用户或 Codex 提供/选择，经用户确认作为项目风格参考；记录原图、项目归属、来源、文件摘要及版本。参考图可以是已有角色图，但选择其风格不等于采用角色身份。

明确区分图像角色：风格参考只引导色彩、光影、材料、影像处理；角色身份母版负责长相或机体；物品母版负责外观结构。请求中明确哪张图做什么，不把它们默认为同一用途。

参考图会随模型请求发送给供应商，使用前确认其为项目授权素材和当前模型支持的格式、尺寸、数量与价格；不将本地图片公开到任意位置。模型不保证精确复制视觉风格或只读取指定元素，须实际审阅。

## 从档案到图片请求

完整档案可以充分详细；给特定模型的实际请求由 Codex 根据当前素材、视图和目标模型挑选所有相关且有区分度的细节，与主体描述、视图和参考图角色组合。不要将整份档案和全剧设定无差别倾倒到每张图，也不要由代码机械截断文字或静默删除约束。

核对当前模型实际接口建议。Seedream 官方建议中文提示词约不超过300字、英文不超过600词；这是效果建议，不是本Skill创造的硬上限。超过时指出可能忽略细节，保留用户明确需要的约束，由 Codex 整理不矛盾的适配版本；不可把字数多或短当作质量保证。

项目风格、当前素材身份/外观、单一视图、位置与声音分层；素材自身结构不能被风格参考覆盖。项目整体风格与单个镜头的合理光照变化可以共存，不强迫所有图同一构图。

## 审阅与版本

产出用户可读风格摘要、后台详细风格稿、模型请求版和参考图清单。版本化风格与实际图片源，保存每次生成实际使用的风格版本、参考用途及内容摘要；修改风格只影响之后的请求，不改写旧任务、旧图、镜头批准或成片。

比较候选时控制被比较的视图、主体、光线与参考链，分别观察风格、身份和物品结构。横向比较多张图只是判断方法，单张可解码/同色或文本相同不证明全片一致。未观察实际图就标未验。

制作风格文字、预览和保存不等于批准付费生成。遵守项目暂停、图片预算、模型范围、真实费用/预占和人类审核；绝不自动批量抽卡或重试未知请求。
