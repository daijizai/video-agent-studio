# 角色资产

用户提供故事与人物想法，Codex 补足设计、视图计划和内部提示，不要求用户逐项写机器参数。用 [角色交接模板](templates/character.md)，执行前读 [公共交接合同](../../docs/PRODUCTION_HANDOFF.md)。

## 设计蓝图

先读取当前项目、剧本、风格和已有资产，区分主体：

- 人类：年龄段、体型轮廓、脸部结构、发型、完整服装层次、鞋与必要配件。
- 人形机器人：比例、头部/视觉面板、躯壳、关节与双手、材料、固定标记和动作能力。
- 动物或其他非人角色：类型、体态、识别结构、毛皮/外壳及合适视图。

只填适用项，不用发型、肤色或人类生理属性强行描述机器人。握笔、翻纸等剧情要求须在设计中有可用的操作部件。

从剧情提取明确事实；缺失细节按项目风格给出有理由的创作选择，标为设计草案，不假称用户已确认。已交给 Codex 决定的选择自行准备，不逐字段反问。

蓝图应说明：稳定轮廓与比例、头脸或视觉部件、完整服装/结构及材料颜色、必要配件、少量身份锚点、允许变化项。不要给每人机械添加痣、伤疤、Logo或过多饰品。精确色值/身高是设计目标，不是生成实测。

基础身份、服装变体和镜头状态分开：表情可变不意味着换脸，某镜的包扎/污渍不应自动固定到所有基础图。

## 项目风格与提示

遵守项目的写实、动画、定格等选择，不所有题材都套“超写实、真人摄影”。标准资产优先简洁背景、均匀可比较光线、中性姿势与清楚轮廓；戏里的应急灯和惊恐动作留到分镜。

内部提示按“主体与设计 → 固定身份/外观 → 当前单一视图 → 构图和可见范围 → 必要保持项”组织。只提取与本图外观有关的项目内容，不粘贴整集对白。

## 母版顺序

1. 选能验证本角色的外观母版。头像可用于人脸选择；服装、双手或结构重要时选择完整正面或另设全身基准，头像不是所有主体的唯一母版。
2. 人工审阅采用身份与全身/结构正面，固定外观、服装及相对比例。
3. 依据镜头需要补独立侧面、背面或细节。引用明确采用的身份/全身原图与版本，不重新从零猜一个“相同角色”。
4. 母版未采用时不自动铺开多角度，也不默认生成全部视图。先交接本批图数、依赖、模型与费用预览。

## 多视图规范

正、侧、背分别保存独立原图和标签。侧面明确主体左/右侧，背面不再次转头露正脸；全身不裁头脚，姿态、主体占比、背景和光线应可比较。头部视图和全身视图分开。

优先中性姿态与弱透视视觉，少遮挡；不把剧情运镜/夸张表演带进标准图。弱透视是目标，不是严格正交或真实扫描。机器人各面保持结构、接缝与材质，不能每一面重新设计外壳。

不以三联画/接触印样作为镜头参考母版；拼版仅审阅展示。模型支持的参考数量、传输和参数由适配器核对。

## 审阅、入库与引用

对实际图片检查完整主体、视图、身份锚点、服装/结构和比例。只做可解码/尺寸检查就写格式已验，不能编造看过图片或语义全部合格。

状态区分设计草案、生成候选、待审阅、人工采用、历史。依据用户对具体图片的明确批准采用，不替用户批准新脸。固定seed/提示或一张参考图不能保证每帧同脸及多角度几何。

原图、设计版本、视图、来源任务、实际模型/请求与文件摘要保留。新候选不覆盖已采用图；旧镜头继续引用旧版本。身份/服装改变产生新设计，镜头主动切换后重新审阅，历史成片不重写。

普通界面只展示名称、可读设计、图片、视图、版本和反馈；哈希、网址与任务请求留后台。AI生成为主，导入为补充；Skill与完整模板不构成生成或重试授权。
