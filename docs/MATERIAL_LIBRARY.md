# 素材资产库：角色与物品

## 普通制作流程

主路径是 **故事/简要设定 → 素材清单 → AI母版 → 人工采用 → 必要独立视图 → 镜头明确引用**。已有图片导入只是补充，不要求用户自己找图。

普通页面不展示机器提示、参考URL、哈希、节点或技术JSON。用户看名称、类型、简要设定、外观版本说明、独立图片、候选/采用版本、生成记录及本次费用。生成前预览本次选中的素材/视图与合计预估，不默认生成全部角度。

只有两种资产类型，没有新增场景分类：

- 角色：头像母版、头部正/侧/背、全身正/侧/背、四分之三视角。先审阅头像母版；已有采用全身正面时，全身扩展优先沿用它，头部扩展优先沿用头部正面/头像。
- 物品：外观主图、正/侧/背、细节。物品独立存在，可关联本项目角色，也可作为镜头参考，不附属于某一个角色。数量、持有人、位置仍属镜头状态，不因挪动物品就创建新身份。

一个视图是一张独立原图，不自动生成拼版。机器请求明确单主体/单构图；模型仍可能违背指令，所以生成完成不代表画面合格或已采用。人工采用前需原图加载成功。需要检查身份、服装、材质、视图和是否多格。

`从故事整理素材` 无网络调用：旧角色直接纳入；从剧本/连续性/提案中按保守物品词表提出带上下文的候选，用户取舍后加入。它不是完整的语义实体抽取，不为整理描述另调用付费文本模型。用户可以新增遗漏项、编辑简要设定。

## 版本与兼容

`asset_library.py` 在既有项目JSON中维护 `material_assets`；每项独立保存 kind、id、versions、latest_version、adopted_version、adoption_history。版本包含名称、设定、外观变体、关联角色和 views；图片记录包含视图标签、独立原图、尺寸/类型/字节数、内容指纹、导入或生成来源。

- 旧 `characters` 通过只读投影显示为角色，保留原 ID、文字、原版本号，不伪造过去未保存的版本；浏览不写库。首次修改只实体化该角色，不迁移所有项目。
- 编辑产生候选版本；只有采用角色文本版本时才同步旧 `characters` 供原流程/CLI使用。仅增加图片或采用同样文字的新视图，不递增旧角色文本版本，避免无意义地让全片审批失效。
- 外观设定/变体变化会清空新候选的视图，历史原图仍在。新生成/导入母版也重新开始候选视图，避免把新面孔或新物品主图与旧角度拼为一套。扩展请求不能把母版与未批准扩展一起生成；必须先采用对应设定的母版。
- 新候选不自动采用，不替换已有采用版本。采用新版也不更新已经固定的镜头引用；取消采用只撤下后续可选的版本，保留历史和已有镜头引用。
- 每个镜头通过 `asset_references` 固定 asset_id、kind、version、name 及具体独立图片快照。本轮已接入的图片模型最多使用3张参考，选择入口作总量限制，不静默丢弃多余引用。
- 修改镜头引用撤销该镜头的文字/图像确认；仅浏览、整理候选、导入、查询、保存未采用候选不撤销旧镜头审批。采用改变角色文本的版本仍遵循原有角色上下文审批失效机制。

`workflow_state` 的新审批/单镜/整片任务匹配附加 `material_binding_version=1` 与引用指纹。历史无素材引用的审批继续使用原逻辑，不批量重写六镜或首版接受记录。`content_snapshot` 深拷贝明确引用，换新采用版本也不能把旧请求伪装为新素材结果。普通 `/api/save` 不允许绕过专门的镜头选材入口覆盖引用。

## 真实生成适配与资金门禁

`asset_generation.py` 复用现有 Qwen Image3.0/Pro 异步适配和 Seedream 5.0 Flash 同步适配。内部描述从已保存设定与视图规则整理；非付费文本推理。扩展时校验明确采用母版的版本/原图，使用其本机原始字节生成 Base64 图片输入，不依赖可能过期的远端URL，也不会改用最新候选。

新镜头图片请求同样通过 `prepare_storyboard` 消费固定素材版本的原图，保留既有手动参考，并遵守总参考上限。视频仍从已批准的镜头画面继续制作，其请求快照保留上游素材引用；不会把未采用的素材图片直接替换成视频输入。

官方协议参考：

- [千问图片FAQ](https://platform.qianwenai.com/docs/resources/faq-images-videos)：Base64 Data URI、图片编辑1–3张参考、10MB及参考尺寸约束。
- [Qwen图片编辑API](https://help.aliyun.com/en/model-studio/qwen-image-edit-api)：image 支持URL/Base64。
- [火山方舟图片生成API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=en)：图片输入与 `data:image/...;base64,...`。模型、输出参数、单张与价格沿用项目已固定的现有适配器，不增加未经核实的参数。

工程保护：

1. 预览只读、零模型调用；每次选择1–8张必要视图，确认时重新计算计划指纹与内容版本。
2. 需要项目/数据库匹配、未暂停、明确图片分类预算、模型授权范围与余额；不得借旧镜头专项增量或视频余额生成素材，不改真实授权文件。
3. 整个计划先预占合计图片费用，任务写入 `image_tasks`，明确 `kind=asset_image`、asset_id/asset_kind/asset_version/target_view，没有假 shot_id，不写视频任务表。未提交计划项可取消并释放其预占。
4. 网络前持久化请求意图/来源/预算绑定；实际提交前再核对授权。公共全局锁只包短事务，不包供应商网络。异步任务编号、同步原结果先持久化再下载；切项目后已提交任务仍归档回原项目，不改当前选择。
5. unknown/submitting 不重提，重复 request_id 不生成第二次；只查询已有编号。明确HTTP拒绝与不确定结果分开。返回多图不拼版、不自动采用或重做，保留结果待核对。
6. 下载失败保留原结果，只重试下载。归档文件用任务绑定名称防止崩溃重试覆写；候选图片保持未采用。所有视图来自同一批次已确认设定或明确旧版本，不将新到候选自动混进已批准镜头。
7. 延续模型平滑间隔、单在途、有限轮询。浏览器只对明确确认且已预占的剩余计划项串行执行；暂停/失败/未知/下载异常会停止推进，不因为刷新预算而解除暂停。

请求快照保存可复原的 material:sha256 清单，避免把大体积Base64像素重复写进每份SQLite历史；保留原图、引用清单和**规范化JSON payload** 的 request_sha256，用于核对实际语义请求（不是认证头或HTTP线上字节哈希）。诊断可看到内部记录，普通用户不需要填这些字段。

## 本机原图与路径安全

- 原图在仓库忽略的 `assets/<project>/library/<image-id>.<format>`，私有目录/文件权限；不自动扫描用户私人目录、不覆盖旧图；管理/导入操作不做外部上传，明确确认生成后才随图片请求发送选定参考原图。
- 浏览器明确选择文件，或选择本项目已登记镜头/图片任务。不能传任意本机路径、跨项目路径或自选远端下载地址。
- 支持PNG/JPEG/静态WebP，单张12MB以内，宽高1–8192、总像素最多1600万。校验扩展名/魔数/块结构/尺寸/长度；PNG校验CRC和有上界的解压像素数据。JPEG/WebP复用本项目已有FFmpeg做受限完整解码；无该已安装工具时明确要求先用PNG，不新增pip依赖。
- 符号链接、路径穿越、跨项目、未登记图片、损坏/截断/超大文件、SVG及动态图拒绝。原图读取再次核对尺寸/指纹，拒绝篡改后采用或生成参考。
- 供应商结果仅从现有固定域名后缀HTTPS下载，有字节上限、无重定向；不把密钥放在下载请求或日志中。`/asset-media/` 只提供当前项目已登记原图，固定Raster MIME、nosniff。

```sh
python3 -m unittest discover -s tests -p 'test_asset*.py' -v
python3 tests/browser_asset_library.py
```

测试使用临时SQLite、临时图片、随机loopback端口和Mock供应商。覆盖两类型/旧角色/空态/独立版本/导入与采用/历史不覆写/母版隔离/镜头引用和实际原图输入/审批绑定/源图篡改/跨项目/路径越界/大小格式/故事提议/同步异步/总预算与模型范围/暂停/unknown/重复请求/原图缓存恢复/项目切换归档，以及手机与原生键盘对话框。

**接入能力与实际产物分开**：测试通过不表示已生成真实角色或物品。当前实际项目保持原暂停、预算与选择，不恢复任何真实生成，不充值、不买套餐、不下载模型或租GPU。实际素材制作需要用户另行明确恢复与有限项目预算。
