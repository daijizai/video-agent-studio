# 创作 Skill 与执行代码交接

## 三个独立入口

- [剧本与分镜](../skills/frame-screenplay/SKILL.md)：标准中文剧本、节奏、镜头和提示交接。
- [角色资产](../skills/frame-character-assets/SKILL.md)：人类/机器人等角色外观、母版和独立多视图。
- [物品资产](../skills/frame-object-assets/SKILL.md)：物品外观、主图、必要视角和剧情道具状态。

分别迭代版本，按需读模板，不默认加载全部知识。旧production入口只兼容路由。通用规范可进Git，实际私人项目材料、数据库、密钥、图片和成片不随Skill公开。

## 分工

Codex 读相关Skill与项目材料，编写剧本、设计蓝图、分镜和内部提示。Skill是自然语言工作规范，不是后端自动执行的程序，也不是新增的付费文本模型。

代码保留可验证的数据合同、模型字段、存储、凭据、预算、审批、任务与文件安全。不能将这些门禁仅写进Skill就从后端移除。运行时配方/哈希可追踪交接来源，不宣称服务端自动像Codex一样理解Skill。

普通界面展示故事、设定、画面、版本、费用和反馈；提示全文、网址、哈希、节点等留后台。不能把机器表单换个名字继续推给用户。

## 持久化

原稿、格式稿、设计稿和分镜分别留版本。保存前核对当前项目与revision，使用已有UI/CLI/HTTP合同，不直接改生产SQLite。改动可逆文字前无需机械重复确认；实际审批和执行按原授权。

CLI支持--url选择本机后端，默认端口以cli.py为准。先列项目和读状态，不能盲用旧示例端口；角色/物品操作按现有素材库接口，不凭模板发明路由。不强制所有模型请求都经ComfyUI。

## 内部生成交接

记录项目、剧本/设计/镜头版本、Skill名与版本、规范来源摘要、明确采用的原图/资产版本、当前视图/动作、保持项、实际模型和费用预览。提示正文只取当前任务相关内容，不全量复制手册。

Skill改版只影响随后准备的材料，不自动重写历史请求、替换参考、批准新图或作废已接受成片。

## 代码继续保证的执行边界

- 读Skill、准备文字或预览不是提交媒体请求。暂停、项目/数据库绑定、模型范围与分类预算逐项检查；预算、模型或Skill编辑不自动恢复执行。
- 明确本次素材/视图/候选数量、阶段依赖和预占；实际账单未知不记作0，不把其它项目额度挪过来。
- 生成完成、候选采用、镜头批准、成片接受分别记录。历史原图和批准来源保留。
- 先持久化意图，再提交一次；有ID查原任务，无ID未知提交保持锁，不自动重提。
- 下载失败只重归档、查询失败只重查询；新增调用服从授权。
- 凭据只由已有仓库外配置消费，不进入Skill、项目JSON、聊天、argv或Git。

## 验证

结构验证只检查metadata、名称和链接。行为验证看实际产物：对白是否保留、非人角色有没有被强填人类属性、物品状态是否混入外观、图片是否单幅、未采用候选是否误作母版。

模板完备和代码测试通过不等于真实画质通过。图片/声音/视频的语义验收须有实际观察证据；额外收费验收调用仍需授权。

## 草案、来源与批次的具体解释

- 离线草案或隔离试用只写用户指定文件时，不需要读取生产数据库或取得项目revision；标明未绑定实际项目。真正回写工作台时才读取当前项目和revision。
- 最小输入是当前任务与用户已有材料。已有授权下，缺少创作细节可自行补成明确的设计草案；缺少必须准确的事实（例如通行证号码）保留未知，不造值或擅自读取其它私人资料。
- 来源说明至少有Skill名、版本与实际读取的规范文件。提交执行时记录各规范/设计文件的SHA256或执行层支持的等价内容摘要；不能手填伪造哈希。该来源清单按已有接口持久化，不因本文件示例而发明API字段。
- 区分完整规划、当前拟授权批次与已经提交的数量。按阶段列依赖与费用，母版未采用的扩展图仍属后续计划，不能提前计作已提交或免费；未选模型的阶段费用写待报价。
