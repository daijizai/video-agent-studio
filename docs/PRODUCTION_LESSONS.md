# 关键帧失败经验与回归

## KF-001 / v1 / 2026-10-28：请求成功不等于分镜合格

- 模型：Qwen Image3.0；请求单张、720×1280、prompt_extend=false。预期单幅静态关键帧，实际输出三格纵向画面。
- 证据：原请求、内容版本、供应商任务号和原图保留在项目SQLite的image_tasks/content_snapshot及忽略的assets目录；项目quality_lessons存关联。公开源码不包含私人原图或项目数据库。
- 判断：供应商生成任务completed，但质量needs_review，不能标为approved，不删除原图，不为修复自动超出次数/预算。
- 根因假设：图片提示混入连续动作、表情变化等时间信息，可能让模型输出多格；也可能受到“分镜”语义或参考布局影响。尚未通过控制实验归因，不断言单一根因。
- 改进：每次只写一个静态瞬间与单一构图；明确禁止多格/拼贴/分屏；把动作先后与对白留在视频prompt。保留必要的剧情视觉（如右侧关闭的门、握钥匙的右手），不机械删除所有剧情词。
- 预检：发现时间码、“随后/然后/先…再/第n镜”等模式时给出警告；不会静默改写用户内容。统一单幅模板进入真实请求并被快照保存。
- 后检：人工查看实际图片、记录多格/身份/空间/道具问题；尚未人工检查时保持unreviewed。可选视觉检查只能辅助，不能伪造人工通过。
- 回归：测试时序提示会被标记、静态视觉可正常保留、实际请求含单幅约束。真实后续效果需看新图验证，不能承诺彻底杜绝多格。

### 后续观察 / v2

保留三联参考、仅增加禁止多格文本的两次输出仍为多格。将参考非破坏地提取为单格、同时改成纯静态提示后的三次输出观察到单幅构图。由于两个条件同时变化，这不是单因素归因实验，也不是未来成功率保证。全部原图、裁剪衍生关系和任务保持可追溯；没有因修复无限增加出图。
